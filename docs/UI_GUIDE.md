# MiniDB 界面规范

界面是 [MyGo](https://mygo.run/) 的原生 UI（纯 Go、立即模式）。这份文档记录视觉与交互上已经定下来的规则，新增界面时照着做，不另起一套。具体的数值和颜色以代码为准：`internal/ui/theme.go`（令牌与尺寸）、`internal/ui/btn.go`（按钮）、`internal/ui/tabstrip.go`（标签）、`internal/ui/grid.go`（数据网格）。

## 1. 气质

桌面数据库工具：信息密度高、层级清晰、克制，参考 TablePlus 和 macOS 的工具软件。数据安全感优先——危险操作要能一眼认出来，并且要二次确认。

不要做：营销页式的大图大字、大面积渐变装饰、卡片套卡片、为普通区域加大圆角。

## 2. 令牌

颜色、尺寸都走 `theme.go` 里的 `tokens` 和常量，业务代码里不写死颜色值。

| 类别 | 规则 |
| --- | --- |
| 底色层级 | `surface`（内容区）→ `surfaceSecondary`（条栏、卡片等次级区域）→ `surfaceElev`（浮层）；工具栏、侧栏、标签栏用 `toolbar`（深色下比内容区略亮，靠明度分层而不是只靠线条） |
| 强调色 | `accent`，**跟随当前连接的颜色**（`Shell.tokens` 已处理）；表达"当前连接的上下文"就用它，不要另起主色 |
| 文字 | `fg` / `fgSecondary` / `fgMuted` 三档 |
| 状态 | `success` / `warning` / `danger` / `info`；禁用只降透明度，不改布局 |
| 分隔 | 边框优先于阴影：`border`（区域分隔、控件描边）、`borderSubtle`（卡片内部细线）；阴影只给弹窗、菜单、浮层，深色下阴影看不见，所以对话框、菜单、提示都再描一圈 `border` |
| 线条对比度 | 两套主题的线对相邻底色的对比度要落在同一档（`border` 约 1.5～1.8:1，`borderSubtle` 约 1.2～1.4:1），不能把浅色的灰直接换成深色的灰；`theme_contrast_test.go` 守着这个区间 |
| 表格底色 | 斑马纹和表头用 `stripe`（对内容区约 1.08:1），不要拿 `surfaceSecondary` 去铺，深色下会过重；行与行靠色差分开，不再加横线 |
| 分段开关 | 轨道 `segTrack`、滑块 `segThumb`，滑块总比轨道更"凸"（两套主题都更亮），`pillTabs` 已处理 |
| 语义色 | 图标按对象着色（表蓝、视图紫、查询绿，`iconColor`）；值按类型着色（数字蓝、时间青，`valueColor`） |

尺寸（DIP）：工具栏 36（`sizeToolbar`）、标准按钮 28（`sizeBtn`）、小按钮 24（`sizeBtnSm`）、标签 28（`sizeTab`）、输入框 32（`sizeInput`）；字号正文 13、密集信息（表格、标签、侧栏）12；圆角按钮 7、面板 12。表格、SQL、标识符用等宽字体 `mono`，工具栏和菜单用界面字体。

## 3. 按钮

只有三个层级，高度、字号、图标、内边距各自固定，**不要在调用处单独设 `Height` / `FontSize`**：

| 函数 | 用在 | 内容 |
| --- | --- | --- |
| `actBtn` / `actPrimary`（24） | 面板、列表、工具栏里的操作 | 图标 + 文字 |
| `fieldBtn` / `fieldPrimary`（28） | 和 28px 输入框同排 | 图标 + 文字 |
| `footBtn` / `footPrimary`（28） | 对话框底部的取消、确认 | 纯文字 |

只有图标的按钮用 `tipBtn` / `toggleBtn`，必须带悬停提示；有快捷键的提示里带上 `keyHint`。

## 4. 标签

主标签栏、查询结果页的「结果 N」、结构视图下半区的「索引 / 外键 / 触发器」是**同一种标签**，外观集中在 `tabstrip.go`：

- 高度 `sizeTab`（28），底边一条贯穿的分隔线，标签之间只隔 1px 竖线，没有空隙；
- 选中的标签铺内容区底色，顶上一道 2px 的连接色线，盖住底线，和下面的内容连成一体；悬浮的标签略微提亮；
- 主标签栏的标签可以关闭（悬浮出现 ×，未保存时显示圆点，中键关闭），右端有「＋」新建查询；结果页等不可关闭的标签用 `tabStrip`（`trailing` 放靠右的操作按钮）。

底部的 Data / Structure / DDL / Doc 和侧栏顶部的「项目 / 查询 / 历史」是另一类：`pillTabs`，圆角分段开关（侧栏里 `grow` 为真，三段等分整行、更高一些）。

## 5. 表格

数据网格和结构视图都建在 `ui.Table` 上，共用同一套外观：

- 主题：`gridSpacing`、12px 等宽字、表头用正文色；行高固定 `gridRowH`，所以下方的斑马纹（`paintGridBg`）能对齐；
- 列宽拖表头边缘调整，列序拖表头挪动，双击边缘按内容适配；
- 行状态用整行底色：新增偏绿、待删除偏红、选中偏强调色（`cellBox` 的 tint 会盖满单元格含内边距，行内没有缝）；
- 选中行不要整行刷成实心强调色（里面的输入框、勾选框会看不清）：给表格换一份"淡强调色"的主题，网格里的控件另用原主题。

### 结构视图（`structview.go`、`objects.go`）

- 上半区是列的网格，**就地编辑**（名称、类型、可空、默认值、备注都是单元格里的控件）；新增行铺绿、待删除行铺红；
- 输入格（名称、类型、默认值、备注、索引名 / 列）点进去拿到焦点时，整个单元格描一圈强调色外框，和数据网格的单元格编辑一致（`ringCellBox` / `paintEditRing`，在 `cellring.go`）；
- MySQL 系数据库可以**拖动行上下换位**调整列序（`ListState.Reorder`，生成 `AFTER` / `FIRST`）；SQLite、PostgreSQL 改不了列序，不给拖动；
- 下半区用 `tabStrip` 切换 索引 / 外键 / 触发器，标签栏右端是当前这一项的「添加」按钮；上下两块之间的分隔条可以拖；
- **索引、外键、触发器都就地编辑，不弹窗**（参照 TablePlus）：「添加」在表格末尾多一行，名称格拿到焦点；名称留空时自动取 `idx_表_列` / `fk_表_列`；
  - 已有的索引、外键也能直接改，提交时先删旧的再建新的（`modified` 状态）；改成空名称 / 空列的索引保持原样，不会误删；
  - 触发器：新增的在单元格里填名称、时机、事件，触发的内容写在右侧编辑器；已有的只能改语句（右侧是完整的 `CREATE TRIGGER`），提交时先删后建；
  - 删除只是标成待删除（红色，可撤销），和列一样等 ⌘S 统一提交；提交顺序是：删旧的外键 / 触发器 → 改列和索引 → 建新的外键 / 触发器（`BuildFullStructureStatements`）；
  - SQLite、StarRocks 不能改已有表的外键，外键页只读；
- 横向滚动到底时，Table 的滚动区右侧还剩一条约 14px 的轨道，单元格铺不到；补满列的单元格画完会登记自己的位置，下一帧由表格这一层把行底色接着铺到边缘（`rowtail.go`），整行才连成一片；
- 数据行隔行铺斑马纹（库自带的斑马纹要开单元格选择，和拖动排序冲突，所以由 `structRowTint` 在单元格里铺），选中的行不铺；
- 选中行后 ⌫ / Delete 删除；右键菜单有上移、下移、删除；提交走 `commitStructure` → `safeGate`，⌘S 提交。

- **工作区栏**（最左边 60px 的竖条）只有开着多于一个工作区时才显示；只有一个或没有连接时不占地方，新建连接用工具栏的按钮或 ⌘N（`layout.go` 里 `len(s.spaces) > 1`）。

### 表级操作

- **新建表**（`tablenew.go`）：侧栏底部「…」菜单 →「新建表」，开一个只有结构页的标签（不进会话）；表名填在结构页顶部的「表名」格，预先有一列 `id`（自增主键），列、索引像编辑已有表一样就地填，新建表时多出「主键」「自增」两列；⌘S 一次建出，建好后变成这张表的普通标签。外键、触发器要建好之后再加；
- **重命名**：已有的表改结构页顶部的「表名」格，随 ⌘S 一起提交（先改列和索引，最后 `RENAME`），标签、侧栏固定项同步改名。视图和只读连接里这一格只读；
- **清空 / 删除表**：确认框里按数据库给复选项——PostgreSQL 有「重置自增序列」「CASCADE」，其余库没有（`database.TableOpSupport`）；SQLite 没有 TRUNCATE，清空用 `DELETE FROM`；
- 鼠标在左侧栏上时，⌘F 搜索的是侧栏的列表（表、查询或历史，停在哪一段就搜哪一段）；在别处仍是数据表的过滤条（⌘⇧F 始终是搜侧栏的表）；
- 侧栏列表的行：鼠标扫过是灰色底（`p.hover`），点选后是强调色淡底，两者不同；
- 侧栏点选一张表后，⌥⌫ 清空、单按 Delete 删除（视图则删除视图），都先确认。键盘归选中的那一行，不是整个列表。

- **项目概览**（`overview.go`）：把当前库所有表和视图列成一张表（名称、类型、引擎、行数、数据 / 索引大小、排序规则、备注、创建 / 更新时间，取不到的显示「—」）。入口：侧栏「表」「视图」标题悬停时右端的图标、右键标题、右键任意一张表、底部「…」菜单。点表头三态排序，右上角筛选名称和备注，双击或回车打开那张表，右键和侧栏的表一致。MySQL、PostgreSQL 的行数是估算值（底部有说明），SQLite 是精确值。每个工作区只有一个概览标签，表增删改名后自动刷新，会进会话。

### AI 助手的回答

回答按 ReAct 的过程**按发生的顺序**一路排下来（`assistant_message.go` 的 `timeline`），不收进折叠的块：推理 →（说明文字）→ 工具调用 → 这一步的结果 → 再推理 → 再调下一个 → 最后一段文字是回答。

- 推理：正在想时展开，标题「思考中 · N 秒」，文字实时流在一条左边线后面；想完收成一行「思考了 N 秒」，点开回看（耗时记在 `agent.Part.DurationMs`，随会话保存）；
- 每一步的标题行：图标块 + 名称 + 对象，右侧是状态（转圈 / 摘要·耗时 + 绿色对勾 / 红色叉），最右的展开箭头悬停才显出、展开时转 90°；新的一步用 `stepTransition` 轻轻淡入，状态图标用 `popTransition`；
- **思维链从哪来**（`internal/ai`）：Responses 的 reasoning summary / reasoning text 事件；Chat 分片里的 `reasoning_content`、`reasoning`、`thinking`、`reasoning_details`；以及正文开头行内的 `<think>…</think>`（`thinkSplitter`）。模型本身不输出推理（如 `deepseek-chat`）时界面上就没有思考行，日志里每轮的 `reasoning_len=0` 可以确认；
- 工具：一行标题（图标、名称、对象、摘要和耗时，运行中转圈），点开是参数、语法高亮的 SQL 和结果。**运行过程中**失败的自动展开（原因 + 建议），最近一次返回了数据表的数据类工具也展开；**回答完成后所有工具自动收成一行**，只留回答（出错没有回答时不收）；
- 回答里的 SQL 代码块点「执行」：块里的语句拆开后全部执行，每条一个结果页；
- 等下一步（还没动静、或刚拿到一个结果还在想）时末尾有一行「思考中…」；
- 没有单独拎到回复外面的「结果卡」，结果总在它那一步后面，和模型的说明对得上。

### 查询结果的翻页

没写 LIMIT 的 SELECT / WITH 查询一次只取一页（默认 500 行，设置 → 编辑器的「结果行数上限」可改），底栏显示「第 1–500 行，共 N 行」，旁边是上一页 / 下一页、第几页 / 共几页和每页行数（100～10000）。翻页只重新执行这一条语句（`gotoPage`），行号接着上一页数，控制台日志里能看到对应的 `LIMIT … OFFSET …`；自己写了 LIMIT 的语句、以及 SHOW / EXPLAIN 这类非 SELECT 的不分页。导出结果仍是不限行数的完整结果。

### 行预览与历史

- **行预览栏只有一份**（`rowpane.go` 的 `rowPane`）：表数据页和查询结果页都用它，字段名在左、类型在右，JSON 用带语法高亮的编辑器。差别只在 `paneSource`：表数据页能就地改值、字段右端有下拉菜单；查询结果页只读、没有下拉箭头。新增行预览的功能改这一处，不要在两边各写一份；
- 行预览和 Quick Look 里的 JSON 编辑器不显示括号配对的描边（`noBracketMatch`），括号和别的字符一样正常显示；
- **历史只在侧栏**：「历史」页按天分组，每天一个可折叠的标题（今天、昨天，其余写日期，折叠状态记在 `side.collapsed["day:日期"]`）；「查询」页（收藏）仍是平铺列表。查询器里不再有自己的历史图标、弹窗和 ⌘Y；「清空历史」在侧栏底部「…」菜单里（历史页才有，收藏的语句保留）。

## 6. 对话框与危险操作

- 对话框统一用 `Shell.dialog`，表单项用 `dlgField`，底部 `footBtn` / `footPrimary`；
- 删除、清空等不可恢复的操作用 `askDanger`（默认焦点在"取消"）；会丢失未保存内容的用 `askWarn`；
- 写库操作经过 `safeGate`（安全模式：静默 / 确认 / 密码），并写入控制台日志；
- 反馈用 `toastOK` / `toastErr` / `toastWarn`，不要用弹窗报告普通结果。

## 7. 国际化

所有用户可见的文字都进 `locales/zh-Hans.json` 和 `locales/en.json`，然后 `go tool mygo generate`，代码里用生成的 `locales.Xxx()`。提交前 `go tool mygo i18n check` 要通过。不再被引用的键要及时删掉。

## 8. 快捷键

窗口级快捷键由 `keymap.go`（按键组合与配置名）和 `shortcuts.go`（统一处理，焦点在哪里都生效）负责，用户可以在设置 → 快捷键里改；新增命令先登记再接处理函数，不要在视图里零散地写全局 `Shortcut`。只在某个元素有焦点时才生效的按键（如表格里的 ⌫）用该元素自己的 `Shortcut`，这样焦点在输入框时按键归输入框。

## 9. 编码约定

- 视图函数每帧都会执行：**不做 I/O**，阻塞操作放进 `uiThread.bg`，结果回到 UI 线程；
- 元素要有稳定的 `c.Key(...)`：位置变化会让 `AutoFocus` 抢走焦点；
- 依赖方向 `ui → app → 领域层`，`app` 和领域包不引用 `mygo/ui`；
- 注释用中文，说明"为什么"，不复述代码。

## 10. 测试与验收

- 界面用 `ui.Tester` 无窗口地跑（`newEnv`、`openWorkspace`、`e.tt.*`），`go test ./...` 覆盖交互；
- `MINIDB_SHOTS=<目录> go test ./internal/ui -run <名字>` 会把 `e.shot(...)` 的截图写成 PNG，改完界面务必看一眼；
- 验收清单：浅色 / 深色都看过（`MINIDB_SHOTS=<目录> go test ./internal/ui -run TestShotsThemes` 会把同一组界面在两种主题下各渲染一遍，方便对照线条）；中英文都不截断；`go vet ./... && go tool mygo vet .`、`go tool mygo i18n check`、`go test ./...` 全部通过；新增行为有对应测试。

## 状态记忆

关闭前是什么状态，重新打开就是什么状态（每 8 秒和退出时存，`SaveState`）：

- 窗口大小和位置：窗口的 `StateKey`；
- 打开的连接、每个连接的标签页（含查询草稿、表标签的子视图和行预览开关）、前台标签、AI 面板开关：`session.go`；
- 侧栏停在哪一段、折叠了哪些分组：同在工作区会话里；
- 侧栏、AI 面板、行预览栏拖出来的宽度，侧栏是否收起，日志面板是否打开及高度：全局布局 `layout_state.go`，新开的工作区也按它来。

新增一个「拖得动 / 开关得了」的界面状态时，要顺手加进这里。

## 设置页与「关于」

- 设置项**一组一张卡片**（和「编辑器」页一样）：卡片里每项一行，左边名称加一句说明、右边是控件（下拉、开关、按钮），项与项之间一条细线（`settingsGroup` 的 `row`）；输入框、主题卡片这类宽控件名称在上、控件在下，也在卡片里（`wide`）。不要一项一个框——框里只有一个标题、右边空着很难看；
- 「关于」页：图标、名称、版本和平台；更新状态卡（检查、下载进度、重启更新、自动下载开关）；仓库、更新日志、反馈、许可的链接；数据和日志目录；复制版本信息；版权。

## 发版与自动更新

- 版本号在 `mygo.json` 的 `version`；`CHANGELOG.md` 里必须有对应的 `## x.y.z` 小节（更新窗口显示它）；
- 发版**全程在本机**，不走线上 CI：改版本号和更新日志 → 提交 → 运行 `scripts/release.sh`。它会跑测试、本地构建并签名（`mygo build -platform darwin/universal -upload`）、上传到草稿 release、打 tag 并推送、再发布成最新版（发布后用户才能更新到）。`DRAFT_ONLY=1` 只上传草稿，到页面检查后手动发布；
- 更新用 `mygo.json` 里 `updates.publicKey` 对应的私钥签名：私钥在本机 `~/Library/Application Support/mygo/update-keys/`，**丢了就再也发不了更新，务必备份**；
- 应用自己管更新流程（`updates.go`，用 `mygo.Updater`）：启动 10 秒后和之后每小时在后台检查（不弹窗），发现新版本**自动下载**（设置 → 关于里可关），下载好后弹一条带「重启更新」按钮的消息，主界面右上角也留着「新版本 x · 重启更新」，点一下重启进入新版本；自动下载关闭时提示是「点击下载」。开发版和没配更新源的构建不检查，「关于」页会如实说明。
